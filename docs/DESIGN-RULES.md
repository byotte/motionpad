# 디자인 전체 규칙 (v1 확정 2026-11-14, 전체 적용 완료 — 기록 `docs/progress/3-K.md`)

**새 화면·새 버튼을 만들 때**: 값은 `src/css/tokens.css`의 이름표만 쓴다. 끝나면 `node tools/design/token_check.js`(0건)와 `node tools/design/inventory.js`(종류 수)를 돌린다. 확정 내용은 맨 아래 '확정 v1'.

0-4b에서 정한 것은 테마 색 3종·대화창 틀·메뉴 구분선·아이콘 도입까지다. 글자·상자·선의 **전체 규칙은 세운 적이 없다.**
아래는 사용자가 2026-11-13에 짚은 규칙이다. 3단계의 '디자인 규칙' 단계에서 보강해 확정하고, **프로그램 전체에 한 번에** 적용한다(부분만 먼저 고치지 않는다).

## 사용자가 정한 방향
1. **글자 위계 세 단계** (프로그램 전체 공통)
   - 큰 메뉴: 굵고 밝게.
   - 하위 메뉴·항목: 그보다 얇고, 그래도 잘 보이게.
   - 단순 도움말: 눈에 덜 띄게. 흐리게만 해서는 체감이 약했다 → **더 어두운(검정 쪽) 색으로 빼되 완전한 검정은 아니게.**
   - 목적: 얼핏 봤을 때 화면에 글자가 너무 많아 보이지 않게.
2. **구분선(묶음 상자)**
   - 한 카테고리 안에서 성격이 다른 것을 나누는 용도(예: 대상 고르기 / 효과 조절). 상자에 제목은 붙이지 않는다.
   - 메뉴 테두리·입력칸과 **다른 색이되 같은 톤으로, 어느 버튼보다도 덜 튀게**(포토샵 '레벨' 창의 묶음선처럼 "나누기만 하는 선"으로 읽혀야 한다).
   - 실패 사례: 강조색(보라)을 바탕에 섞은 선 → 기존 테두리보다 밝아져 가장 튀었다. 쓰지 말 것.
3. **입력칸**: 테두리 선 대신 **어둡게 파인 칸**(사용자 승인: "아주 좋다").
4. **고르는 버튼(둘 중 하나 등)**: 강조색으로 가득 채우지 않는다(너무 튄다). **굵은 테두리의 빈 사각형**으로 선택을 표시.
5. **뜻이 분명한 켜기/끄기는 아이콘으로**: 잠금 = 자물쇠 아이콘, 켜지면 색을 띤다. 이름 칸 옆 '체크박스 + 잠금' 글자는 쓰지 않는다.
6. **크기 맞춤**: 글자 크기가 들쭉날쭉하면 안 되고, 버튼·아이콘 상자는 글자에 딱 맞아야 한다(헐렁한 상자 금지). 시안 수준의 정돈 안 된 크기가 완성품에 나오면 안 된다.

## 진행 방법 (합의)
- 규칙을 먼저 한 장으로 세우고 → 세 테마(다크·라이트·모노)의 실제 화면 견본으로 보여 주고 → 사용자 확정 뒤 패널·대화창·도구줄 전체에 일괄 적용, 화면마다 전후 스크린샷 확인.
- 이전 프로젝트(아스트라)에서 시안 → 본 프로그램 이식 중 누락이 반복돼 접은 경험이 있다. 시안은 실제 프로그램 화면에 입혀서 만들고, 적용 뒤 `style_snapshot.js`·스크린샷으로 빠진 곳을 확인한다.

## 초안 (이름표 = 한곳에 모아 두는 값. 화면에는 이름표만 쓴다)
**글자** — 크기 3단계 + 굵기 3단계만 쓴다.
| 단계 | 쓰는 곳 | 크기(PC / 폰) | 굵기 | 색 |
|---|---|---|---|---|
| 큰 메뉴 | 패널 번호 제목(1. 영역…), 대화창 제목, 상단 메뉴 | 13 / 15 (견본 ①) | 700 | 밝은 글자 |
| 항목 | 옵션 이름, 버튼, 고르는 버튼, 목록, 안내줄 | 12 / 14 | 500 | 밝은 글자보다 한 단계 낮게 |
| 도움말 | 설명글, 단위, 작은 표시 | 11 / 12 | 400 | 어두운 쪽으로 뺌(견본 ②) |
- 숫자 값(35% 등)은 항목 크기 + 강조색. 닫기(×) 같은 기호만 예외 크기.

**상자와 선** — 선 3종, 모서리 2종.
- 틀 선: 패널·대화창·버튼 테두리(지금의 기본 선).
- 묶음 선: 한 카테고리 안을 나누는 선. 제목 없음, 어느 버튼보다 덜 튀게(견본 ③).
- 선택 선: 고른 것을 알리는 굵은(2px) 테두리(견본 ④). 바탕은 채우지 않는다.
- 모서리: 버튼·입력칸 / 상자·대화창 두 값(견본 ⑥).

**입력칸** — 테두리 없이 어둡게 파인 칸(글자 입력, 목록 고르기 공통). 깊이는 견본 ⑤.

**크기와 간격**
- 버튼·입력칸·목록 높이: PC 26 / 폰 36(손가락) 한 값. 접는 제목 PC 28 / 폰 38.
- 버튼 안쪽 좌우 여백: 글자 버튼 10, 아이콘 버튼은 정사각형.
- 간격은 4·8·12 세 값만(항목 사이 8, 묶음 사이 12, 글자와 값 사이 4).

**상태 표시** (모든 버튼 공통)
- 평소 / 마우스 올림(선이 강조색) / 누름(바탕 한 단계 어둡게) / 꺼짐(흐리게 45%) / 선택됨(선택 선) / 키보드 초점(강조색 1px 바깥선).
- 뜻이 분명한 켜기·끄기는 아이콘(잠금 등), 켜지면 강조색.

**바탕색** — 화면 바탕 / 패널 / 버튼 / 파인 칸 / 강조 5종만. 지금의 미세하게 다른 10여 종은 이 다섯으로 모은다.

## 적용 때 누락 방지(확정 후)
1. 위 값을 `tokens.css`에 이름표로 추가 → 다른 CSS의 숫자·색을 이름표로 교체.
2. 검사: `tokens.css` 밖에 색·글자 크기·굵기·모서리 숫자가 남으면 목록으로 출력(0이 목표, 예외는 사유를 적는다).
3. `node tools/design/inventory.js`를 다시 돌려 종류 수가 목표(글자 크기 3+예외, 굵기 3, 모서리 2 …)로 줄었는지 확인.
4. 전 장면 전후 스크린샷(`style_snapshot.js`, `shots.js`) 세 테마 × PC·폰.

## 초안에서 바뀐 점(적용하며 확인)
- 바탕 "5종만"은 지키되, 제목줄·마우스 올림·안내 바탕·슬라이더 길은 그 다섯에서 계산한 파생값 4종으로 따로 이름을 붙였다(위계 표시에 필요).
- 키보드 초점 표시는 지금까지 쓰던 강조색 2px 선을 그대로 둔다(초안의 '1px 바깥선'은 취소).
- 간격 이름표는 패널의 항목·묶음·대화창 안쪽에 적용했다. 도구줄·상단바처럼 화면 폭에 맞춰 조여 둔 곳의 간격은 그대로다(검사 대상은 색·글자 크기·굵기·모서리).
- 도구줄의 고른 도구(아래 강조색 줄), 영역 목록의 고른 줄(옅은 강조 바탕), '플레이' 버튼(강조색 채움)은 '고르는 버튼'이 아니라서 예전 표시를 유지했다.
- 잠금은 이름 칸 오른쪽 자물쇠 아이콘으로 옮겼다(켜지면 강조색).
