# 원본 검토 결론 (Fable 진단 + GPT·Gemini 교차 검토 반영본)
CLAUDE.md는 이 문서의 요약이다. 판단 근거가 필요할 때만 이 문서를 읽는다.

## 교차 검토에서 받아들인 것
- outlineCosts는 누적 비용이 아니라 경로상 최대 장벽(minimax)이다. 선화 뒤 픽셀은 fg·bg 비용이 모두 ≈255가 되어 차이 0 → threshold 1 미달로 탈락한다. 머리카락·옷 선택 실패의 직접 원인이다. (Gemini)
- 선택 실패는 384 격자와 알고리즘 두 원인이 겹친 것이다. "격자만이 원인"이라는 첫 진단은 과장이었다.
- 영역별 개별 텍스처는 불가능하다. 텍스처 슬롯 6개를 이미 쓰고 있고 WebGL1 보장 최소치는 8개다.
- 분리 레이어를 모든 영역으로 일반화하면 볼·몸통 경계가 찢어진다. 연속 변형 영역과 분리 영역을 구분한다. (Gemini)
- 다중 ES 모듈은 file://에서 로드되지 않는다. 배포본은 단일 HTML로 유지한다.
- 기준선 없이 대규모 개편을 하면 회귀가 반복된다. 기준선 확보를 최우선으로 한다. (GPT)
- RLE runs가 TILE*TILE을 전제한다(포맷 v2). 해상도를 바꾸면 저장·복원·되돌리기를 묶어 데이터 모델 변경으로 설계해야 한다. 되돌리기 상한은 35개, 약 9MB다. (GPT)
- 2048 타일 4×3 RGBA 아틀라스는 약 192MiB라 모바일에서 불가능하다. (GPT)

## 부분 수용
- 채널 패킹은 텍스처 슬롯 문제만 푼다. 영역당 uniform vec4가 12개라서 48개 영역이면 576개가 되고, 보급형 모바일 상한인 약 256개를 넘는다. 설정값도 데이터 텍스처로 옮겨야 한다. 12개 초과가 필요한지부터 확인한다.
- 재계산 문제는 dirty 플래그가 있어 입력마다 일어나지는 않는다. 정확한 설명은 "드래그 중 프레임마다"다. feather·spread는 tail 원본 마스크에 영향이 없으므로 재계산은 순수한 낭비다. (GPT 정정)
- 메시는 이미 있지만(rebuildMesh) 정점 셰이더는 전체 흔들림만 담당한다. 접촉 변형은 프래그먼트 변위에 가우시안/RBF 당김을 더하는 방식으로 먼저 구현한다. 메시 엔진 교체는 철회한다. (GPT)
- 자석 올가미가 고해상도에서 나빠진다는 주장은 계측 대상이다. (Gemini)

## 버린 것
- "AI 모델 금지 위반"이라는 비판. 원래 요구에는 그런 조건이 없었다. 다만 청사진 원칙에 따라 MobileSAM은 기본 계획에서 빼고 허락 시 실험으로만 둔다.
- "1·2단계 전체가 무효"라는 단정과 경쟁 서술.

## 개발안 v2
0-1 기준선: 코드는 수정하지 않는다. PC·폰 세로·폰 가로 스크린샷(Playwright), 저장→불러오기 왕복 테스트, updateMasks·buildBackgroundPlate·updateBlinkScene·render 시간 계측을 만든다. 확정 레이아웃 치수를 문서화한다.
0-2 확정 결함 수정: tail 재계산은 원본 마스크가 바뀔 때만 한다. 영역별 dirty 플래그를 둔다. 옵션 조작은 모드를 바꾸지 않고 '터치 미리보기' 플래그로 처리한다(도구를 누르면 해제, 미리보기 보존을 테스트한다). 앱 자체 메뉴를 만든다. 몸체 지정 때 값을 덮어쓰지 않는다.
0-3 속성 스키마 단일화: 저장 형식은 바꾸지 않는다. 왕복 테스트로 검증한다.
0-4 CSS 재작성: 토큰 체계와 브레이크포인트 2개로 다시 쓰고, 런타임 DOM 조립을 제거한다. 스크린샷 비교로 검증한다.
0-5 파일 분리: 개발은 분리된 파일로 하고, 배포는 합치기 스크립트로 단일 HTML을 만든다(효과음 포함).
1-A 선택 알고리즘: 동점은 '미결정'으로 분류한다. 전경에 둘러싸인 미결정·배경 섬은 메운다. 얇은 선화는 장벽을 감쇠한다. 올가미 바깥 띠에서 배경색 모델을 만든다. 선화가 있는 테스트 세트로 터치 수와 IoU를 측정한다.
1-B 고해상 마스크(가설): 영역 바운딩 박스만 원본 해상도로 저장한다. 포맷 v3에 격자 크기·박스를 기록하고 v1·v2는 384를 업샘플해 변환한다. 되돌리기는 영역 차분 방식으로 바꾼다. 경계 오차·메모리 피크·undo 크기를 측정한다.
1-C 영역 수 확장(필요 시): 채널 패킹 + 데이터 텍스처, 또는 WebGL2 텍스처 배열을 쓴다. 기기 상한을 먼저 조사한다.
2 움직임: 연속 변형 영역(기본)과 분리 영역(사용자 지정)을 구분한다. 분리 영역을 2~3개로 늘리기 전에 앞뒤 순서·배경 소유권·노출 영역 규칙을 정한다. PatchMatch는 분리 영역 뒤 빈자리에만 쓰고 기존 보간과 비교한다. 접촉 변형은 RBF로 하고, 5.5% 상한 완화 시 접힘이 보일 때만 메시 혼합을 실험한다. 깜빡임은 계측 결과에 따라 패치 단위 GPU 합성으로 옮긴다.
3 완성도: 기본 대화창 제거, 단축키, 안내 문구 한 곳으로 통합.
실험 트랙: MobileSAM(허락 시만).
원칙: 한 번에 한 단계, 매번 기준선 비교, 정리 단계 기능 추가 금지, 가설은 실험 전 본 개발 금지.
