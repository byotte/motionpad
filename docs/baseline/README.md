# 0-1 기준선 (legacy 0.5 RC23, 코드 수정 없음)

이후 모든 단계는 이 폴더의 결과와 비교한다. 측정일 2026-11-12.

## 다시 재는 법
```bash
python3 tools/baseline/make_fixture.py        # 테스트 그림(이미 커밋됨, 바꿀 때만)
node tools/baseline/run.js <대상.html> <이름>  # 결과 → tools/baseline/out/<이름>/
python3 tools/baseline/compare.py docs/baseline/legacy-0.5rc23 tools/baseline/out/<이름>
```
- Playwright(환경에 기본 설치)만 쓴다. 조작은 실제 사용자 경로(파일 선택·클릭·드래그)로만 한다.
- 스크린샷은 시계·난수를 고정해 찍는다. 같은 코드를 두 번 재면 차이가 0.12% 이하라서, **0.2% 넘게 달라지면 실제 변화**로 본다.
- 성능 수치는 헤드리스 Chromium + 소프트웨어 WebGL(SwiftShader) 기준이다. 실기기 수치가 아니며, **같은 기계에서 전후 비교용**이다. 재실행 흔들림 약 ±5%.

## 확인된 것 (CLAUDE.md 결함 목록과 대조)
- **간략 범위지정 실패 재현**: `select-outline-draft.png`. 꼬리를 넉넉히 둘러쌌는데 꼬리 위쪽 배경에 가는 띠만 잡힌다. outlineCosts 동점·탈락 문제와 맞아떨어진다. 처리 시간도 8초대로 길다.
- **슬라이더 드래그 낭비 재현**: 드래그 프레임마다 dilateMask(마스크 확장)와 텍스처 재업로드가 반복된다. 0-2 수정 후 이 두 값이 크게 줄어야 한다.
- **'선택에 더하기' 해제 시 동작**: 이전 영역을 리셋하지 않고 새 영역을 하나 더 만든다. 청사진("해제 상태에서는 이전 영역 리셋")과 다르다. 타원을 그리면 이 체크가 자동으로 다시 켜진다.
- 마술봉은 옷 가운데 세로선에서 멈춰 옷 왼쪽 절반만 잡는다. 선이 뚜렷한 그림이라 정상 동작으로 본다(비교 기준으로만 기록).

## 참고 (재현 미확인)
- 첫 시험 실행의 플레이 화면에서 그림 오른쪽 가장자리가 중간 높이에서 1~2px 어긋난 모습이 한 번 찍혔다. 이후 실행에서는 보이지 않았다. 흔들림 위상에 따른 것인지 2단계(움직임)에서 다시 본다.
