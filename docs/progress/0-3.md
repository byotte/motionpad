# 0-3 영역 속성 단일 스키마 결과

## 한 일
`motionpad.html`의 `ZONE_FIELDS`(속성표) 하나에 영역 속성 47개를 정의했다. 저장 순서, 기본값·범위, 연결된 입력칸, 표시 형식, 이동 스냅샷 여부가 한 줄에 들어 있다.
원래 6곳에 따로 나열되던 코드를 모두 이 표에서 자동으로 만든다.

| 원래 위치 | 지금 |
|---|---|
| `clean` (저장) | 표 순서대로 `save` |
| `sanitize` (불러오기 검사) | 표의 `read` + 실행 상태는 `zoneRuntime()` |
| `updateUI` (입력칸에 값 넣기) | 표의 `ui.input`·`toInput` |
| `updateValues` (숫자 표시) | 표의 `ui.output`·`fmt` |
| 입력 연결 2곳 (값 반영, 되돌리기 기록) | 표의 `ui` 항목에서 자동 연결 |
| `snap` (이동·변형 시작 모양) | 표의 `snap` |

새 속성을 추가할 때는 표에 한 줄을 넣고, 화면에 입력칸 HTML을 하나 넣으면 끝난다.

## 검증
- 동등성 검사기 `tools/baseline/schema_check.js`: 일부러 이상한 값(빈칸·범위 밖·문자열·null·모르는 종류·긴 이름·남는 속성)을 섞은 영역 12개로 원본과 비교했다.
  ① 불러온 뒤 저장 ② 영역별 입력칸·숫자 표시 ③ 모든 입력을 한 번씩 바꾼 뒤 저장 ④ 되돌리기 5번 뒤 저장 → **네 가지 모두 원본과 글자 단위로 같다**.
- 검사기 감도 확인: 기본값 하나, 표시 형식 하나, 저장 순서 하나만 바꾼 사본 3개를 만들었더니 셋 다 '다름'으로 잡혔다.
- 전체 측정기: 저장 파일 크기·내용, 선택 결과, 시계 고정 스크린샷 모두 0-2와 같다. 오류 0건.
