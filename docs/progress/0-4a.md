# 0-4a CSS 재작성 결과 (겉모습 유지)

## 한 일
1. **실행 중 화면 재조립 제거**: 테마·화질 선택, 플레이어 줄, 감상 화면 효과음 선택, 도움말 말풍선, 선택 영역 표시 창을 처음부터 HTML에 둔다.
2. **죽은 UI 제거**: 진입로 없는 '움직임 추가' 창, 숨겨진 '모두 반응' 버튼, 쓰지 않는 toolHelp 창, 항상 숨겨져 있던 하단 안내문(footer).
3. **CSS 새로 쓰기**: 47KB, 7겹 지층, 구분점 17종 → 27KB, 11개 구획, 구분점 2개.
   - 색 토큰 3종(다크·모노·베이직)을 맨 위 한 곳에 모았다. 버튼 글자색 `--onAccent` 토큰을 새로 뒀다.
   - 구분점: **폰형**(세로 화면이거나 폭 779px 이하), **좁은 폰**(폭 520px 이하). 터치 기기용 높이 조정은 구분점이 아니라 입력 방식 조건(pointer:coarse)으로 둔다.
   - 그 사이 값(옵션 패널 폭 250~315px, 도구 탭 글자 10~12px, 흐름 방향 버튼 높이)은 `clamp()`로 화면 폭에 맞춰 부드럽게 바뀐다. 측정한 화면 크기에서는 원본 값과 정확히 같다.

## 검증 방법
- `tools/baseline/css_usage.js`: 브라우저(CDP)에 장면 97개에서 '각 요소에 실제로 적용된 선언'을 물었다. 한 번도 적용되지 않은 선언을 걷어낸 축소본(36KB)이 원본과 97개 장면 모두 같음을 확인했다. 새 CSS는 이 축소본을 토대로 썼다.
- `tools/baseline/style_snapshot.js`: 97개 장면(화면 7종 × 상태, 테마 3종, 대화창·메뉴·감상 화면·윤곽 보정·도움말 등)에서 모든 요소의 위치·크기·색·글꼴·테두리·여백을 원본과 비교했다.
- 전체 측정기(`run.js`): 시계 고정 스크린샷, 저장 왕복, 선택 결과, 동작 시험, 오류. 속성 동등성 검사(`schema_check.js`).

## 결과
- 스타일 스냅숏: **97개 장면 중 75개 완전히 같음**. 나머지 22개는 아래 '받아들인 차이'뿐이다.
- 스크린샷: 폰 가로 화면 2장(0.31%, 상단 메뉴 글자)만 다르고 나머지는 원본과 0.00%.
- 저장 파일·선택 결과·동작 시험·속성 동등성: 0-3과 같다. 오류 0건.

## 원본에서 발견한 어색한 점 (0-4b에서 정리할 후보)
원본의 규칙 겹침 때문에 생긴 모양이라 0-4a에서는 그대로 옮겼다.
- 대부분의 버튼 테두리색이 투명해서 테두리가 안 보인다(원본의 ID 섞인 규칙이 덮어씀).
- '화면 이동' 탭만 글자가 10px로 다른 탭보다 작다.
- 축 버튼 셋 중 '축 추가'만 글자가 12px이고 나머지는 10px이다.
- 터치 기기에서 선택상자는 커지지 않고 26px로 남는다(버튼은 40px).
- 소리 창의 '감상 화면에 음악 플레이어 표시' 체크박스 글자가 사라지고 칸이 어긋난다.
- 모노 테마의 캔버스 바탕색이 토큰(--stageInk)이 아닌 고정색(#e8ebf2)이다.
