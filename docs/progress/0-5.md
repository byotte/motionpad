# 0-5 파일 분리 + 단일 HTML 합치기

## 한 일
- 한 파일(약 440KB)이던 `motionpad.html`을 `src/` 아래 36개 파일로 나눴다. 구성과 파일별 내용은 `src/README.md`.
  - `css/` 10개: 0-4a에서 나눈 구획(색 토큰·기본·공용 컨트롤·상단바·시작 화면·편집 화면·옵션 패널·대화창·감상 화면·화면 크기별) 그대로.
  - `html/` 3개: 아이콘 모음 · 앱 본문 · 대화창.
  - `js/` 20개: 주제별(영역 속성표, 선택 엔진, 입력, 마스크, 셰이더, 렌더, 물리, 눈 깜빡임 등). 1단계 '선택 엔진'은 `js/selection.js`(약 18KB)만 보면 된다.
  - `sfx/` 4개: 217KB짜리 base64 한 줄이던 효과음을 원래 wav 파일로 되돌렸다.
- 합치기 스크립트 `tools/build.js`(외부 패키지 없음, Node만): `src/index.html`의 `@@include` 줄을 파일 내용으로, `@@base64(…)`를 효과음 base64로 바꿔 `motionpad.html` 한 파일을 만든다. 약 5ms.
  - `--watch`: 고칠 때마다 자동으로 다시 만든다. `--check`: 결과물이 src/와 같은지 확인. `--out`: 다른 곳에 만든다.
  - 줄바꿈 빠진 파일, 처리 안 된 지시어, src/ 밖 경로는 멈추고 알려 준다.
- JS는 예전처럼 `<script>` 하나, 즉시 실행 함수 하나 안에 순서대로 이어 붙는다. ES 모듈을 쓰지 않으므로 결과물은 file://로 열어도 그대로 동작한다.
- 분리는 줄 단위 연속 구간으로만 했다(코드 한 글자도 고치지 않음). 1회용 분리 스크립트는 남기지 않았다.

## 검증
- **합친 결과가 0-5 직전 `motionpad.html`과 바이트 단위로 같다**(sha256 `ddb2e0a2…`). 효과음 4개도 wav → base64가 원래 문자열과 정확히 같게 돌아온다.
- 측정기(`run.js`) 0-5 직전(pre05) ↔ 합친 결과(post05):
  - 시계 고정 스크린샷 48장 모두 0.00%.
  - 실시간 스크린샷은 `select-all-zones` 0.22% 외 0.05% 이하. 애니메이션 위상 차이(기준선 문서상 0.7%까지 흔들림). 파일 바이트가 같으므로 실제 변화일 수 없다.
  - 저장 왕복(이미지·설정 동일, 98,383바이트), 선택 결과(마술봉 5,875 · 외곽 591), 동작 시험 5종, 페이지 오류 0건 모두 같다.
  - 성능 수치는 재실행 흔들림 범위 안.
- `--watch`로 고쳤다 되돌리면 결과물이 원래와 같아지는 것, 줄바꿈 빠진 파일에서 멈추는 것을 확인했다.

## 이후 작업 방식
- 고치는 곳은 `src/`. 커밋 전에 `node tools/build.js`로 결과물을 다시 만들고 `--check`가 '일치'인지 본다. 결과물 `motionpad.html`도 함께 커밋한다(배포본이자 측정 대상).
