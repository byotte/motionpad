# 3-K 디자인 전체 규칙 확정·일괄 적용

규칙은 `docs/DESIGN-RULES.md`(확정 v1). 사용자가 부품 견본판(`img/design-board-1.png`)에서 여섯 가지를 골랐고, 그 값을 이름표(`src/css/tokens.css`)로 만들어 스타일 전체에 한 번에 입혔다. 기능은 바꾸지 않았다.

## 한 일
- 조사: `tools/design/inventory.js` — 실제 화면(PC·폰, 편집 화면·대화창·메뉴)에 쓰인 값의 종류를 센다.
- 이름표: 글자 색 3단계·크기 3단계·굵기 3단계, 바탕 5종(+파생 4종), 선(틀·묶음·선택), 모서리 2종, 높이 3종, 간격 3종.
- 일괄 교체: CSS 9개 파일의 글자 크기·굵기·모서리·색을 이름표로. 직접 적혀 있던 색 21곳과 계산식 색도 이름표로 옮김.
- 부품 규칙: 입력칸·목록 고르기 = 테두리 없는 파인 칸 / 고르는 버튼 = 떨어진 버튼 + 고른 것은 강조색 굵은 테두리(바탕 채움 없음) / 묶음 상자·접는 묶음·영상 세부 설정 = 묶음 선 / 잠금 = 이름 칸 옆 자물쇠 아이콘.
- 폰형 글자 15·14·12, 손가락 기기 버튼 높이 36·제목줄 40.
- 누락 검사: `tools/design/token_check.js` — `tokens.css` 밖에 색·글자 크기·굵기·모서리 값이 직접 적혀 있으면 알려 준다.

## 확인
- `token_check.js` 0건, `build --check` 일치, 화면 오류 0.
- `schema_check` 완전히 같음(잠금을 아이콘으로 옮긴 뒤에도 잠금 저장·되돌리기 동일), `shape_check` 11단계·`selop_check` 9단계 통과.
- `run.js`(3-J 끝 → 지금): 저장 왕복 동일, 선택 결과 동일(마술봉 5874, 외곽 2826). 저장 파일 101,049 → 101,045바이트: 파일을 나란히 대조했고, 시험이 화면 좌표로 그리는 영역의 좌표 소수 자릿수만 달랐다(제목줄 높이가 바뀌어 캔버스 크기가 달라진 탓, 3-C 때와 같은 종류).
- 성능 수치는 이번 실행이 더 빠르게 나왔으나 헤드리스 측정 잡음으로 본다(스타일만 바꿈).
- 눈으로 본 화면: PC 세 테마 × 패널 2상태·영상·설정·소리·눈 깜빡임 창, 폰 다크·라이트. 그림은 `img/3-K-panels.png`, `img/3-K-phone.png`.
- 폰 아래 줄(되돌리기·확대·돋보기·손가락 보정·영역선): 390·412px 한 줄, 폴드 겉화면 344px 두 줄(이전과 같음). 캔버스 높이는 그대로.
- 스타일 전수 비교(`style_snapshot.js`)는 돌리지 않았다. 전 화면의 스타일이 의도적으로 바뀌는 단계라 차이 목록이 전부 '의도'가 되기 때문이다. 다음 단계부터 이 결과물을 새 기준으로 쓴다.

## 남은 것 / 실기기에서 볼 것
- 도움말 글자(다크·모노 B)는 고른 대로 많이 뺐다. 실제 폰 밝기에서 읽히는지.
- 폰에서 버튼 높이 36이 누르기 편한지, 옵션 칸이 좁게 느껴지지 않는지.
- 점검표 '디자인 규칙 단계에서 볼 것' 가운데 이름·설명·배치 문제(올가미 옵션 이름, '터치 이동 방향 자동', 속도 항목 둘, 눈 적용 표시, 판 번호 등)는 글자·선 규칙과 별개라 이번에 손대지 않았다.
