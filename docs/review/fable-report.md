# 페이블 전체 검수 보고서 (2026-11-17)

기준 커밋 `9a2e94b`. 코드는 고치지 않았다. 검수 범위·형식은 `docs/review/fable-review.md`를 따랐다.

## 요약
- **전체 평가**: 기능 폭과 검사 도구는 탄탄하고, 빌드 일치·디자인 이름표 검사도 통과한다. 다만 최근에 얹은 얼굴 기능이 기존 기능(원본 크기 녹화, 빈자리 채우기, 되돌리기)과 만나는 자리에서 실제 오류가 난다. 화면은 색·버튼·글자가 통일돼 있지만, 옵션이 한 줄로 길게 쌓이는 구조라 기성 프로그램에 견주면 '정돈된 느낌'보다 '긴 설정 목록'에 가깝다.
- **가장 급한 것 3개**
  1. 원본 크기로 영상을 저장할 때 눈이 깜빡이면 그림 왼쪽 위에 줄어든 그림이 겹쳐 찍힌다(E1).
  2. '빈자리 채우기'를 켠 영역 안에 얼굴이 있으면 표정·홍조·빨개짐이 보이지 않는다(E2).
  3. 되돌리기가 '아무 일도 안 한 것'을 한 칸으로 세고, 입 찍는 중 되돌리면 앱 오류가 난다(E3·E4).

## 1. 오류

### E1. 원본 크기 녹화 중 눈 깜빡임이 그림을 망가뜨린다 — 높음 [재현]
- 위치: `src/js/blink.js:56-58`(uploadBlinkTexture), `src/js/render.js:123-126`, `src/js/export-hires.js:49-51`
- 문제: 원본 크기 녹화는 그래픽 카드에 올린 그림을 큰 그림으로 바꿔 놓는다. 그런데 눈 깜빡임은 '같은 크기일 것'이라 믿고 편집용(긴 변 1900px) 그림을 **왼쪽 위 구석부터 덮어쓴다**. 큰 그림 위에 작은 그림이 구석에 붙는다.
- 틀어지는 상황: 긴 변이 1900px보다 큰 그림 + 눈 깜빡임 적용 + 영상 크기 '원본'. 녹화 시작 약 1초 뒤 첫 깜빡임부터 끝까지 망가진 채 저장된다. 2600×2600 네 색 그림으로 시험: 깜빡임이 없으면 정상, 있으면 (45%,45%) 자리가 빨강 → 노랑(줄어든 그림의 오른쪽 아래 칸)으로 바뀌었다.
- 고치는 방향: 원본을 올린 동안(hiResActive)에는 깜빡임 그림도 원본 크기로 만들어 올리거나, 그동안은 `texImage2D`로 통째 교체. `tools/motion/hires_check.js`에 깜빡임 있는 경우를 추가.

### E2. '빈자리 채우기' 영역 안의 얼굴에는 표정·홍조·빨개짐이 안 보인다 — 높음 [재현]
- 위치: `src/js/shaders.js:105-114`(tailLayer), `:214`, `:227-228`, `:238-241`
- 문제: 표정(휘기)과 붉은 기운은 바탕 그림에만 계산한다. 빈자리 채우기 영역은 그 위에 **따로 얹는 그림**이라 표정이 적용되지 않은 원래 얼굴이 위를 덮는다.
- 틀어지는 상황: 머리·얼굴을 포함한 영역에 '빈자리 채우기'를 켠 경우. 시험에서 같은 '부끄러움 100%'가 일반 영역에서는 눈썹·입·홍조가 바뀌었고, 빈자리 채우기 영역에서는 땀방울만 보였다. 알림도 없어 사용자는 고장으로 느낀다. 맞은 자리 '빨개짐'도 같은 이유로 가려진다.
- 고치는 방향: 얹는 그림을 읽을 때도 같은 얼굴 이동량·붉은 기운을 적용(tailLayer에 `faceShift`·`faceRed`). 당장 어렵다면 그 조합일 때 안내를 띄운다.

### E3. 입을 찍는 중에 되돌리기로 얼굴이 사라지면 앱 오류 — 중간 [재현]
- 위치: `src/js/face.js:122-127`(faceMouthTap), `:60-63`(applyFaceHistory), `src/js/zones.js:4`
- 문제: 되돌리기가 얼굴을 없애도 '입 찍기' 도구는 그대로 남는다. 세 번째 점을 찍는 순간 없는 얼굴에 값을 넣다가 오류가 난다(`Cannot set properties of undefined (setting 'mouth')`).
- 틀어지는 상황: 얼굴 '적용' 켬 → 입 찍기 → 되돌리기 → 그림을 세 번 누름. 안내줄은 '입 가운데를 눌러 주세요'에 멈춘다. 눈썹·귀 그리기도 같은 구조다(귀는 한 획 뒤 되돌리면 지운 획이 다음 획과 함께 되살아난다 [코드]).
- 고치는 방향: 되돌리기·다시 실행 때 얼굴 지정 도구에 있으면 하던 도구로 돌려보내고 찍던 점(faceDraft)을 비운다. 찍는 함수 첫머리에서 얼굴이 있는지 확인.

### E4. 되돌리기가 '빈 칸'을 만든다 — 중간 [재현]
- 위치: `src/js/zones.js:77`, `src/js/controls.js:26`·`:65-66`, `src/js/zones.js:3`(remember)
- 문제: 조절 막대는 값을 바꿀 때가 아니라 **누르거나 초점이 갈 때** 되돌리기 지점을 만든다. 만지기만 하고 값을 안 바꿔도 한 칸이 쌓인다. 선택한 영역도 기록에 들어 있어, 영역만 바꿔 고른 뒤 막대를 누르면 '영역 선택'만 다른 칸이 또 생긴다.
- 틀어지는 상황: 세기를 40으로 바꾼 뒤 다른 막대를 눌렀다 떼고 되돌리기 → 첫 번째는 아무 변화 없이 '실행 취소했습니다'만 뜨고, 두 번째에야 26으로 돌아온다. '되돌리기는 늘 마지막에 한 일' 원칙에 어긋난다.
- 고치는 방향: 누를 때는 그때 모습을 따로 들고만 있다가, 값이 실제로 바뀐 첫 순간에 기록에 넣는다.

### E5. 표정 창의 되돌리기가 창을 열기 전 작업까지 되돌린다 — 중간 [재현]
- 위치: `src/js/face-dialog.js:117`, `src/js/zones.js:5`

## 2. 구성 · 스파게티

### 지금 고쳐야 할 것

**S1. 같은 식이 두 벌(그림용 셰이더 / 화면 위 표시용 JS)이고 이미 어긋나 있다 — 중간**
- `shaders.js:115-212` ↔ `render.js:65-105`(cpuDeformation), `shaders.js:68-91`(faceRed) ↔ `face-engine.js:279-286`(redAt).
- E8·E11이 여기서 나온다. 한쪽만 고치면 조용히 어긋나는 구조다.
- 방향: 상수(한계값·반경·주기)를 한 곳에 두고 양쪽이 읽게 한다. 두 계산이 같은 값을 내는지 보는 시험을 `tools/motion`에 추가.

**S2. 그래픽 카드에 올린 그림을 여러 파일이 제각각 덮어쓴다 — 중간**
- `image-viewer.js:2`, `masks.js`(syncBaseTexturesGL), `blink.js:56`, `export-hires.js:49-57`. '지금 올라간 그림의 크기'를 아는 곳이 없어 E1이 났다.
- 방향: 올리는 함수를 하나로 모으고 현재 크기를 기억하게 한다.

**S3. 되돌리기 기록을 여러 창이 함께 쓰는데 규칙이 창마다 다르다 — 중간**
- 편집 화면(누를 때 기록) · 표정 창(같은 기록을 빌려 씀, E5) · 눈 깜빡임 창(자기만의 기록 `blinkUndoStack`). E3~E5의 뿌리다.
- 방향: '기록 만들기'를 한 함수로, 창은 열 때의 깊이를 넘지 못하게.

**S4. 한 묶음 실행 구조의 약한 고리 — 중간**
- JS 31개 파일이 즉시 실행 함수 하나에 이어 붙는다(`src/index.html:29-61`). 어느 파일이든 맨 바깥 줄에서 오류가 나면 **그 뒤 파일이 전부 실행되지 않아** 앱이 통째로 멈춘다. 뒤 파일의 `let`·`const`를 앞 파일이 함수 안에서 쓰는 곳이 많다(예: `face-engine.js`가 `face-dialog.js`의 `exprDialog`·`exprZoom`·`currentExpr`를 씀). 지금은 순서가 맞아 문제없지만 파일 순서를 바꾸면 바로 깨진다.
- 실제 화면 구동에서는 콘솔 오류가 없었다(시험 중 E3 외 0건).
- 방향: 빌드 때 '맨 바깥에서 뒤 파일 변수를 쓰는 곳'을 검사. 매 프레임 `try/catch`(`controls.js:217`)는 오류를 콘솔에만 남기므로, 같은 오류가 이어지면 한 번은 화면에 알린다.

### 3-3. 기성 프로그램(포토샵·클립스튜디오)과 견준 평가

객관적으로 보면 **'부품' 수준은 기성 프로그램에 가깝고, '배치' 수준은 아직 설정 화면에 가깝다.**

잘 된 점
- 색·테두리·글자 크기가 이름표로 통일돼 화면 어디서나 같은 부품이 같은 모양이다. 선 아이콘도 굵기가 고르다. 고르는 버튼의 굵은 테두리, 강조색 숫자는 일관되고 눈에 잘 들어온다.
- 강조 버튼이 '플레이' 하나뿐이라 시선이 흩어지지 않는다.
- 안내줄, 도움말 점, 상황별 확인창은 기성 프로그램보다 초보자에게 친절하다.
- 파일 메뉴의 구분선·단축키 표기, 대화창의 제목줄·× 위치는 익숙한 문법 그대로다.

모자란 점(큰 것부터)
1. **패널이 한 줄로 긴 목록이다.** 포토샵은 패널을 탭·접기로 나눠 한 번에 한 주제만 보이고, 클립스튜디오는 도구 속성과 보조 도구가 따로다. MotionPad는 영역·얼굴·몸체·부분 움직임이 한 스크롤에 이어져 '순서대로 채우는 설문지'처럼 보인다(L9).
2. **단계 구분이 모양으로 드러나지 않는다.** 기성 프로그램은 패널 제목 → 묶음 → 항목이 바탕색·글자 굵기로 세 단계가 뚜렷하다. 여기는 2~4단계가 같은 꺾쇠 상자다(L1).
3. **캔버스가 고정돼 있지 않다.** 도구를 바꿀 때 그림이 움직이는 것은 기성 프로그램에 없는 일이다(L8).
4. **메뉴 위치.** 파일·소리·설정이 오른쪽 끝, 플레이 옆에 있다. 관례는 왼쪽(로고 옆)이다. 청사진의 '최상단'은 지키지만 파일 메뉴를 찾는 눈길은 왼쪽으로 먼저 간다. 왼쪽에 메뉴, 오른쪽에 플레이만 두면 강조도 더 산다.
5. **첫 화면이 비어 있다.** 버튼 셋이 위쪽에 작게 있고 나머지는 빈 바탕이다. 기성 프로그램은 최근 작업 썸네일·끌어다 놓기 영역이 있다. '5분 안에 결과물' 목표라면 샘플 그림 썸네일, '그림을 여기에 끌어다 놓으세요', 3단계 안내(영역 칠하기 → 움직임 고르기 → 플레이)가 여기 있어야 한다.
6. **조절 막대 모양이 둘이다.** 패널은 두 줄(이름·숫자 위, 막대 아래), 표정 창은 한 줄(이름·막대·숫자). 표정 창 쪽이 촘촘하고 기성 프로그램에 가깝다. 패널도 한 줄로 바꾸면 길이가 거의 절반이 된다(L9 완화).
7. **숫자를 직접 칠 수 없다.** 기성 프로그램은 막대 옆 숫자를 눌러 값을 입력한다. 여기는 막대뿐이라 폰에서 '35 → 36' 같은 미세 조절이 어렵다.
8. **영역 목록이 레이어 패널 구실을 못 한다.** 보이기·숨기기(눈 아이콘), 순서 바꾸기가 없다. 겹친 영역은 뒤 순서가 위인데 순서를 바꿀 길이 없다. 잠금·이름·효과 꼬리표는 잘 돼 있다.
9. **눈 깜빡임 창과 표정 창의 문법이 다르다.** 눈 창은 큰 보라 '현재 눈 적용' 버튼 + 자기만의 되돌리기, 표정 창은 바로 반영 + 편집 화면 되돌리기. 같은 섹션에서 여는 두 창이 다른 프로그램처럼 느껴진다.
10. **마술봉 기본값 '교체'의 위험.** 영역을 고른 채 마술봉을 누르면 새 영역이 아니라 **고른 영역의 모양이 바뀐다**(되돌릴 수는 있다). 포토샵에서 새 선택이 기존 레이어를 건드리지 않는 것에 익숙한 사람에게는 뜻밖이다. 영역이 이미 있을 때는 기본을 '더하기'로 하거나 바뀌는 순간 안내줄에 '영역 1의 모양을 바꿨습니다'를 띄우는 편이 안전하다.

**P5. 표정 창이 열려 있는 동안 화면 두 개가 함께 돈다 — 중간 [코드, 폰 실측 못 함]**
- `face-dialog.js:50` + `face-engine.js:265-306`: 미리보기는 최대 720×720 화소를 JS로 하나하나 계산한다(프레임당 약 50만 화소). 그동안 창 뒤 편집 화면도 계속 그린다. 원본 그림 전체 화소 사본(`faceSrc`, 1900px 그림이면 약 14MB)은 창을 닫아도 남는다.
- 방향: 창이 열린 동안 뒤 화면은 쉬게 하고, 창을 닫을 때 사본을 버린다.

**P6. 자동 저장이 그림 파일을 매번 다시 쓴다 — 낮음 [코드]**
- `storage.js:15`: 막대를 움직일 때마다(0.7초 뒤) 원본 그림까지 통째로 다시 저장한다. 큰 그림이면 폰 저장 공간에 부담.
- 방향: 그림은 바뀔 때만, 설정은 따로 저장.

**P7. 0.7초마다 도는 이름 표시 — 낮음 [코드]**
- `dialogs.js:74` `setInterval(paintProjectName,700)`: 이름이 안 바뀌어도 화면 글자와 탭 제목을 계속 다시 쓴다. 이름이 바뀌는 곳에서만 부르면 된다.

참고: 되돌리기 한 번에 눈 조각을 다시 만드는 비용을 의심했으나 재 보니 3~10ms로 문제없었다.

## 5. 프로젝트 규칙 위반

**R1. '적용 버튼 없음' — 눈 깜빡임 창의 '현재 눈 적용' — 낮음 [재현, 의도일 수 있음]**
- `blink.js:460`. 3-M 원칙('고르면 바로 반영')과 다르다. 점 네 개를 찍어야 하는 특성 때문일 수 있으나, 그렇다면 예외로 적어 두는 편이 좋다. 창을 그냥 닫으면 찍은 점이 말없이 사라지는 것도 함께 볼 것.

**R2. '되돌리기는 늘 마지막에 한 일' — E4·E5**
- 빈 칸(E4), 창 밖 작업까지 되돌림(E5), 창마다 다른 기록(S3).

**R3. '디자인 값은 이름표만' — 캔버스에 그리는 색은 검사 밖 — 낮음 [재현]**
- `token_check.js`는 CSS만 본다. JS가 캔버스에 직접 그리는 색이 따로 적혀 있다: `overlay.js`의 청록 계열(`#83ffd3`, `#7ef1c1`, `#102a31de`, `#e6fff8` — 예전 teal 테마 잔재), 축 노랑 `#ffcf70`, `face.js:156-159`. 라이트·모노 테마에서도 같은 색이다.
- 방향: 편집 표시용 이름표(선택 선·손잡이·이름표 바탕)를 `tokens.css`에 두고 JS가 읽어 쓴다.

**R4. '단일 HTML' — 지켜짐, 단 두 가지 메모**
- 배경음악 6곡은 고를 때 물어보고 인터넷에서 받는다(`audio.js:41-53`). 사용자 자료를 보내지는 않으므로 '서버 전송 금지'에는 어긋나지 않는다. 다만 파일만 받은 사람이 인터넷 없이 열면 '몽환적인'만 된다는 안내가 있는지 확인할 것 [확인 못 함].
- 없는 파일 두 개를 가리킨다(E13).

**R5. '확인창' — 대체로 지켜짐 [코드]**
- 영역 삭제·얼굴 삭제·눈 제거·추가 축 삭제·프리셋 불러오기·새 그림·프로젝트 열기·닫기 모두 상황별 문구. 브라우저 기본 창(alert·confirm·prompt)은 0건.
- 확인 없이 지워지는 것: 가지 선 삭제(`zones.js:67`, 되돌리기 가능), 표정 창 '자리 처음으로'(되돌리기 가능). 둘 다 되돌릴 수 있어 문제 삼지 않아도 된다.
- 시작 화면 '샘플 그림으로 체험하기'는 자동 저장본이 있을 때만 묻는다. 맞는 동작이다.

**R6. '지정이 끝나면 하던 도구로' — 지켜짐 [코드]**
- 축·가이드 선·입·눈썹·귀 모두 `placeReturn`으로 돌아간다. 예외는 E3(되돌리기로 대상이 사라진 경우).
